# setlist.app — Changelog

## Current Release

### v3.7.0 — Guitar Chord Diagrams

**Status:** Current

Brief summary:
- **Keyboard or Guitar:** the chord panel has a **Keyboard | Guitar** switch. Your choice applies to every chord and is remembered in that browser.
- **Guitar diagram:** a fretboard drawing (`×` muted, `○` open, `Nfr` when the shape sits higher up) plus a tab line, for example `x32010` for C (low E to high e).
- **Pick a shape:** each chord offers up to 3 shapes: **Open**, **E shape, fret n** and **A shape, fret n**. Barre shapes move to the chord's root.
- **Wider coverage:** guitar shapes for every chord quality the app reads (aug, m6, dim7, add2/4/9, 9, maj9, m9, 11, 13, 7b9, 7#9, 7#5, 7b5, 7#11, maj7#11, maj7#5, 6/9 and more). Slash chords such as `C/G` rebuild the shape so the bass note is the lowest.
- **More chord spellings read on the sheet:** `7(b9)`, `maj7(#11)`, `-7`, `69`, `6add9`, `7sus`, `9sus`, `mM7`, `madd9`, `7b5`, `7#11`, `maj7#11`, `maj7#5` (also on the keyboard).
- Keyboard users can reach the panel: pressing Enter on a chord moves focus into it, and Escape returns focus to the chord.
- Fixes: slash chords with a bass outside the chord (`C/D`, `C/Bb`) now show a note name instead of a number; the panel closes on scroll or resize; only one panel is open at a time.
- **No lyrics or chords are changed**, nothing is saved to the database, and **Export PNG** is untouched. No migration.

## Previous Releases

### v3.6.0 — Chord Diagrams

Brief summary:
- **Chord diagrams:** hover a chord in **Lyrics + Chords** (desktop) or tap it (phone and tablet) to see a piano keyboard drawing of that chord. On phones and tablets the panel **stays** until you dismiss it.
- **Pick a voicing:** each chord offers 2–4 shapes — Root position, 1st/2nd/3rd inversion, and for slash chords a **Bass note lowest** shape. The keyboard and the note list both change when you pick another one.
- Notes are spelled the way the chord is written: `C9` shows **Bb**, not A#, and `Bb` major shows Bb·D·F.
- Slash chords mark the bass note with a heavier outline, so `D/F#` reads as F# lowest.
- **No lyrics or chords are changed**, nothing is saved, and **Export PNG** is untouched.
- On share links the diagram matches the key the viewer switched to.
- No migration and no database change.
- Works anywhere a chord sheet is shown: the event editor, a share link, the library song preview and the Add songs preview.

### v3.5.0 — Live-performance Tools

Brief summary:
- **Section Notes sit beside the song** on tablet and PC (right side, always visible, and they follow you as you scroll) instead of in a tab. On phones they fold into a slim **Section Notes (n)** bar above the tabs; tap it to open.
- **Metronome:** a round ▶ button next to the tempo fields clicks and flashes at the song's BPM. It keeps running when you switch songs and picks up the next song's tempo. It also works on share links.
- **Tap:** a **Tap** button next to BPM (in events and when adding or editing a library song) sets the BPM from your taps (average of the last 6; a 2-second pause starts over). In events the metronome follows it.
- **Autosave:** in the event editor, changes save 1.5 seconds after you stop editing. After a failed save it waits for your next edit instead of retrying. **Save** still works.
- **Reference link** (YouTube, Spotify, ...) on library songs and event songs; adding a library song to an event copies it.
- New songs start with **no Section Notes** (library imports and pasted chord sheets no longer create one per section heading).
- New migration: `supabase/migrations/007_song_url.sql` (required: the song pages fail without it).

## Previous Releases

### v3.4.0 — Choose What to Export

Brief summary:
- **Export PNG** opens a pop-up ("Which version?") with **Lyrics Only**, **Lyrics + Chords** or **Section Notes**. One click downloads that PNG and closes the pop-up.
- File names: `<Title>.png` for Section Notes (unchanged), `<Title> - Lyrics.png` and `<Title> - Chords.png` for the two lyrics versions.
- On share links, the export uses the key the viewer switched to.
- Songs with no lyrics yet have the two lyrics options disabled ("No lyrics yet").
- No migration and no database change.

### v3.3.0 — Filters, Last Update & Confirmed Previews

Brief summary:
- **Events:** filter by **Owner** and by **month** (e.g. "Oct 2026"), and sort by event date with **Date ↑ / ↓** (newest first by default; undated events last).
- **Library:** filter by theme with checkable theme chips (a song shows if it has any checked theme), and each song shows when it was **last updated**.
- **Add songs:** the pasted text stays in the box after **Preview** (Preview again updates the card). Each ready card has a **Confirm** button, plus **Confirm all ready**. **Save** saves only confirmed songs and warns if some ready previews aren't confirmed.
- **Add songs defaults:** rhythm starts at **4/4** and BPM empty, unless the sheet has `Time:` or `Tempo:` lines.
- New migration: `supabase/migrations/006_song_updated_at.sql`.

### v3.2.0 — Library Pages, Themes, Rhythm & BPM

Brief summary:
- **Sidebar navigation** with **Events**, **Library** and **Theme**. Inside an event, the same links sit in the top bar.
- **Library page:** all songs A–Z with filters by text and theme. Each song has its own page to view, edit (details and lyrics/chords) or delete it.
- **Add songs page:** paste a chord sheet or upload files, preview every song, then save. Replaces the old Upload songs page (`/library/upload` redirects).
- **Themes:** a Theme page to create, rename and delete themes, and tag songs with them. Deleting a theme removes it from all songs.
- **Rhythm and BPM** on library songs, copied into events on import and editable next to the key. `Tempo:`/`Time:` lines in pasted or uploaded sheets fill them in.
- **Event owner:** a free-text owner per event, shown on the Events list and on share links.
- New migration: `supabase/migrations/005_library_details.sql`.

### v3.1.0 — Song Library, Lyrics & Chords

Brief summary:
- Added a shared **song library** (`songs` table, `supabase/migrations/004_song_library.sql`) with fast search by any part of the title or lyrics.
- Added **Upload songs**: bulk upload of ChordPro or plain "chords above lyrics" text files, with a preview that flags duplicates, missing keys and unreadable files before saving.
- **Add Song** now searches the library and imports a song's lyrics, chords and key into the event as an editable copy. Section Notes are pre-filled with the song's sections. **Add blank song** keeps the old behaviour.
- Each song has three tabs: **Lyrics Only**, **Lyrics + Chords** (chords above the words, instrumental bars as `| E . . . |`) and **Section Notes**.
- **− / +** on the key transposes the chords (flats in flat keys). On share links it changes only the viewer's display.
- Songs are stored as ChordPro. Events and songs from before v3.1.0 keep working (no lyrics yet).

### v3.0.0 — Next.js, Accounts & Dashboard

Brief summary:
- Rebuilt setlist.app as a Next.js (TypeScript) app hosted on Vercel. The look and the editor features are unchanged.
- Added sign-in with Supabase Auth. **Testing mode for now:** everyone logs in with one shared password to one shared account; there is no sign-up. Email + password and Google sign-in were built and can be restored from git history (see README, "Switching to real accounts").
- Added a **Dashboard** listing your events (name, date, song count) with **New event**, and per-event **Edit**, **Share** (copies the read-only link) and **Delete**.
- Events are private to their owner (Row Level Security). Share links (`/share/<token>`) stay public and read-only, and old `?share=<token>` links redirect to them.
- The editor has **← Dashboard**, **Save** and **Share** (copies the read-only link). It warns before you leave with unsaved changes.
- Added a **Team** pop-up per event (free-text name and role per member), editable in the editor and read-only on share links. Stored in a new `members` JSONB column (`supabase/migrations/003_event_members.sql`).
- Removed `?edit=` links, the "Event saved" popup and the Reset button: ownership and **New event** replace them.
- Events saved before v3.0.0 have no owner. Their share links keep working, but they can no longer be edited.
- The event and share pages show an error page for unexpected database errors instead of a misleading 404. Unknown links still show 404.

### v2.3.0 — Supabase Persistence, Edit Links & Simplified Saving

Brief summary:
- Events are now saved to a **Supabase** `events` table instead of the browser's localStorage. Configure the project URL and publishable key in `supabase-config.js`.
- Added a **Save** button to the header. Saving opens an **"Event saved"** popup with an **edit link** (`?edit=<event id>`) to reopen and keep editing the Event later.
- The popup has a **Share** button that copies a read-only link (`?share=<token>`) to the clipboard automatically, plus a **Copy edit link** button. If clipboard access is blocked, the link is shown with a Ctrl+C / ⌘C hint.
- After saving, the address bar switches to the edit link, so refreshing or bookmarking keeps the same Event.
- Share links are no longer snapshots: they always show the latest saved version of the Event.
- **Reset** now starts a new Event: it clears the page and removes `?edit=` from the URL, so the next Save creates a new Event instead of overwriting the previous one.
- Removed the standalone **Share** button and the **Actions** menu (Export JSON / Import JSON). Saving and edit links replace JSON backups.
- Fixed a share-link bug that referenced an undefined variable after saving.
- The shared view no longer loads the Event id, so the edit link isn't exposed to viewers through the UI.

> **Security note:** anyone with an edit link can edit that Event. With open row-level security policies, anyone holding the publishable key can read or modify any Event; add Supabase Auth before using the app with other people.

### v2.2.0 — Event Sharing (View-only Links)

Brief summary:
- Added a **Share** button to the header. It opens a **"Shareable link ready"** popup showing a view-only link to the current Event, with a **Copy link** button. Copying closes the popup and shows a "Link copied to clipboard" toast.
- The whole Event (name, date, Songs, Song Details, colors, notes) is compressed and encoded into the link's URL fragment (`#share=...`). No backend or account is needed, and it works on static hosting such as GitHub Pages.
- Opening a share link shows a **read-only view**: viewers can switch Songs, toggle Light/Dark Mode, and Export PNG, but cannot edit, add, delete, reorder, import, export JSON, or reset.
- Viewing a shared link **never overwrites the viewer's own saved Event**. Persistence is disabled in view mode.
- Added a banner in view mode ("Viewing a shared setlist · read-only") with an **Open my setlist** link back to the viewer's own data.
- Invalid or damaged links show an error banner and fall back to the viewer's own Event.
- Shared data is validated through the same normalization as JSON import, and oversized payloads are rejected.
- Read-only Song Details show multi-line notes in full.
- Share links are **snapshots**: later edits require sharing a new link.
- On phone widths (≤680px), the theme toggle shows its icon only, so the header fits the new Share button.
- Storage key remains `setlistApp_v2_0_0`, since the data model is unchanged.
