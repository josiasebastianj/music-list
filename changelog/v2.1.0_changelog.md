# setlist.app — Changelog

## Current Release

### v2.1.0 — Visual Redesign & UX Restructuring

**Status:** Current

Brief summary:
- Introduced a new editorial Light Mode + modern Dark Mode visual direction.
- Changed navigation to **Sidebar = Song Navigation / Main = Active Song Workspace**.
- Removed Song Collapse/Expand.
- Removed Song-level Notes.
- Added Actions dropdown for JSON operations.
- Kept Theme toggle and Reset as direct header controls.
- Improved responsive/mobile layout.
- PNG export follows the active Light/Dark theme.
- Added consistent `setlist.app`, author, and version branding to app footer and PNG export.
- Preserved the v2.0.0 multi-song architecture and core functionality.

---

## Previous Releases

### v2.0.0 — Multi-Song Architecture

**Brief summary:**
- Major data-model upgrade from a single Song to multiple Songs per Event.
- New structure: **Event → Songs → Song Details**.
- Added Song navigation, add/delete/reorder, collapse/expand, and Song-level PNG export.
- JSON became Event-level and supports all Songs.
- Added migration from the previous single-song data model.
- Initial/reset state contains an Event with no Songs.

### v1.5.2 — Terminology / UI Copy Baseline

**Brief summary:**
- Standardized user-facing terminology to:
  - Event Date
  - Event Name
  - Add Song Detail
- Established the final v1.5.x single-song baseline used as the foundation for v2.0.0.
- No version bump was required for the terminology-only adjustments.

### v1.5.1 — English UI Consistency

**Brief summary:**
- Standardized all visible application text to English.
- Updated labels, placeholders, confirmations, errors, tooltips, and accessibility text.

### v1.5.0 — Initial / Reset State

**Brief summary:**
- Made the initial app state exactly match the Reset state.
- Default Event metadata and Song Title were blank.
- Reset restored the same clean baseline consistently.

### v1.4.9 — State & Persistence Hardening

**Brief summary:**
- Improved state normalization and localStorage handling.
- Added safer reset rollback when persistence fails.
- Improved JSON import validation and file-read error handling.
- Improved JSON export cleanup and section-name normalization.
- Cleaned the section color palette.

### v1.4.8 — Stability & Export Fixes

**Brief summary:**
- Fixed JSON import so Event metadata and Base Key are preserved.
- Fixed Reset persistence.
- Improved PNG height calculation for long notes.
- Added section color validation.
- Sanitized PNG filenames.
- Removed duplicate render assignments and hardened section normalization.

### v1.4.7 — Post-1.4.6 Bug-Fix Release

**Brief summary:**
- Follow-up release after the v1.4.6 redesign.
- Identified and addressed several data persistence, import, export, and rendering issues that were subsequently hardened in v1.4.8.

### v1.4.6 — Song Details Export Redesign

**Brief summary:**
- Redesigned the exported PNG Song Details layout.
- Moved notes to the right side with larger, more readable typography.
- Aligned Song Title with the Base Key border.
- Improved export title/date/service metadata.
- Preserved editable Song Details, notes, colors, reorder, persistence, JSON, and PNG workflows.

## Versioning Notes

- **v1.4.x → v1.5.x:** iterative stability, UX, terminology, and persistence improvements.
- **v2.0.0:** major release because the underlying data model changed from one Song to multiple Songs per Event.
- **v2.1.0:** visual/UX release built on the v2.0.0 architecture.
- Minor copy-only changes do not necessarily require a version bump.
