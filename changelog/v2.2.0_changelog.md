# setlist.app — Changelog

## Current Release

### v2.2.0 — Event Sharing (View-only Links)

**Status:** Current

Brief summary:
- Added a **Share** button to the header. It opens a **"Shareable link ready"** popup showing a view-only link to the current Event, with a **Copy link** button. Copying closes the popup and shows a "Link copied to clipboard" toast.
- The whole Event (name, date, Songs, Song Details, colors, notes) is compressed and encoded into the link's URL fragment (`#share=...`). No backend or account is needed, and it works on static hosting such as GitHub Pages.
- Opening a share link shows a **read-only view**: viewers can switch Songs, toggle Light/Dark Mode, and Export PNG, but cannot edit, add, delete, reorder, import, export JSON, or reset.
- Viewing a shared link **never overwrites the viewer's own saved Event**. Persistence is disabled in view mode.
- Added a banner in view mode ("Viewing a shared setlist · read-only") with an **Open my setlist** link back to the viewer's own data.
- Invalid or damaged links show an error banner and fall back to the viewer's own Event.
- Shared data is validated through the same normalization as JSON import, and oversized payloads are rejected.
- Read-only Song Details show multi-line notes in full.
- Share links are **snapshots**: later edits require sharing a new link.
- On phone widths (≤680px), the theme toggle shows its icon only, so the header fits the new Share button.
- Storage key remains `setlistApp_v2_0_0`, since the data model is unchanged.

## Previous Releases

### v2.1.0 — Visual Redesign & UX Restructuring

**Brief summary:**
- Introduced a new editorial Light Mode + modern Dark Mode visual direction.
- Changed navigation to **Sidebar = Song Navigation / Main = Active Song Workspace**.
- Removed Song Collapse/Expand.
- Removed Song-level Notes.
- Added Actions dropdown for JSON operations.
- Kept Theme toggle and Reset as direct header controls.
- Improved responsive/mobile layout.
- PNG export follows the active Light/Dark theme.
- Added consistent `setlist.app`, author, and version branding to app footer and PNG export.
- Preserved the v2.0.0 multi-song architecture and core functionality.

### v2.0.0 — Multi-Song Architecture

**Brief summary:**
- Major data-model upgrade from a single Song to multiple Songs per Event.
- New structure: **Event → Songs → Song Details**.
- Added Song navigation, add/delete/reorder, collapse/expand, and Song-level PNG export.
- JSON became Event-level and supports all Songs.
- Added migration from the previous single-song data model.
- Initial/reset state contains an Event with no Songs.

## Versioning Notes

- **v1.4.x → v1.5.x:** iterative stability, UX, terminology, and persistence improvements.
- **v2.0.0:** major release because the underlying data model changed from one Song to multiple Songs per Event.
- **v2.1.0:** visual/UX release built on the v2.0.0 architecture.
- **v2.2.0:** feature release (sharing). The data model and storage key are unchanged.
- Minor copy-only changes do not necessarily require a version bump.
