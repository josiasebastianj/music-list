## 2. Feature Overview

### Sharing (owner)

1. Click **Share** in the header.
2. The app builds a link that contains the whole current Event and opens a
   **"Shareable link ready"** popup. The popup shows the link in a read-only field and explains
   that the link is view-only and a snapshot.
3. Click **Copy link**. The link is copied to the clipboard, the popup closes, and a
   **"Link copied to clipboard"** toast confirms it.
4. If the browser blocks clipboard access, the popup stays open, the link is selected, and a
   hint asks the user to press Ctrl+C / ⌘C.
5. **Close**, Escape, or clicking outside the popup dismisses it without copying.

The link is a **snapshot** of the Event at the moment Share was clicked. Later edits are not
reflected, so share a new link after making changes.

An Event with no Songs can still be shared; viewers see the empty state.

### Viewing (recipient)

Opening a share link shows the Event in **view mode**:

| Allowed | Not available |
|---|---|
| Read Event Name and Event Date | Edit anything |
| Switch between Songs in the sidebar | Add / delete / reorder Songs or Song Details |
| Read Song Title, Base Key, Song Details, colors, full notes | Change Song Detail colors |
| Toggle Light / Dark Mode | Share, Actions menu (Export / Import JSON), Reset |
| Export PNG for a Song | |

- A banner under the header reads **"Viewing a shared setlist · read-only"**, with an
  **Open my setlist** link that returns to the viewer's own data (same page, no share fragment).
- The viewer's own saved Event in localStorage is **never read into or overwritten by** the
  shared Event.
- An empty Event Date is hidden in view mode instead of showing an empty date field.
- Multi-line notes are shown in full (the editor's single-row note field is not used).

### Invalid links

If the link is truncated, edited, or otherwise unreadable, an error banner says **"This share
link is invalid or damaged."** The app then opens the viewer's own Event normally.

## 3. Technical Design

### Link format

```text
https://<host>/<path>/index.html#share=<payload>
```

- The data lives in the **URL fragment** (after `#`). Browsers never send the fragment to the
  server, so the shared content does not reach GitHub Pages or any server logs.
- `<payload>` = base64url( deflate-raw( JSON( compact event ) ) ).

### Compact payload (version 1)

```js
{
  v: 1,                 // share format version
  n: "Event Name",
  d: "2026-10-04",      // Event Date (may be "")
  s: [                  // Songs
    {
      t: "Song Title",
      k: "G",           // Base Key
      x: [              // Song Details: [name, color, note]
        ["Intro", "#8fc5ff", "Pad only"]
      ]
    }
  ]
}
```

- IDs are not included. They are regenerated on decode by `normalizeSong` /
  `normalizeSections`.
- Short keys plus compression keep links small. A 10-song Event with 8 Song Details per Song
  and a typical note on each encodes to roughly 350 characters.
- A future format change should bump `v`. `decodeShare` rejects unknown versions.

### Functions (`index.html`)

| Function | Role |
|---|---|
| `encodeShare(event)` | Builds the compact payload, compresses it with `CompressionStream("deflate-raw")`, and returns base64url |
| `decodeShare(str)` | base64url → `inflateCapped` → JSON → maps back to the Event shape → `normalizeEvent`. Returns `null` on any failure |
| `inflateCapped(bytes)` | Streams `DecompressionStream("deflate-raw")` and aborts after `MAX_SHARE_BYTES` (1,000,000) |
| `toBase64Url` / `fromBase64Url` | URL-safe base64 without padding |
| `initShare()` | Runs at startup. If `location.hash` starts with `#share=`, decodes it and enables view mode, or shows the error banner |
| `viewHeader(song)` / `renderDetailView(section, root)` | Read-only rendering of the Song header and Song Details |
| `showBanner(message, isError)` / `showToast(message)` | View-mode/error banner and "link copied" toast |
| `#shareBtn` handler | Encodes the Event, puts the URL into `#shareUrl`, opens `#shareDialog` (native `<dialog>` via `showModal()`) |
| `#copyShareBtn` handler | `navigator.clipboard.writeText`. On success, closes the dialog and shows the toast. On failure, selects the URL and shows `#shareHint` |

### View mode

- `viewOnly` (module-level flag) is set by `initShare()` when a valid link is decoded.
- `persist()` returns `true` immediately when `viewOnly` is set, so nothing is written to
  localStorage.
- `document.body` gets the `view-only` class. CSS hides `#shareBtn`, `#actionsMenu`,
  `#resetBtn`, and `#addSong`.
- `#eventName` and `#eventDate` are set to `readOnly`.
- `renderMain()` / `renderDetail()` branch on `viewOnly` and render text elements instead of
  inputs. Edit controls are not rendered at all.
- `exportSongImage()` is unchanged and works in view mode, since it only reads `state`.
- A `hashchange` listener reloads the page, so pasting a different share link into an open tab
  loads it.

### Startup order

```js
initTheme();
initShare().finally(render);
```

## 4. Security / Safety

- **Untrusted input:** decoded data goes through the same `normalizeEvent` path as JSON import.
  All strings are coerced, colors are validated by `safeColor` (anything other than `#rrggbb`
  falls back to the default), and all text is rendered through `esc()`.
- **Decompression bomb:** the inflated size is capped at 1 MB, and larger payloads are rejected
  as invalid.
- **Privacy:** anyone who has the link can read the Event. Links cannot be revoked. Treat them
  like the content itself.

---

## 5. Limitations

- **Snapshot only.** Links do not update when the owner edits the Event.
- **No link previews per Event.** Chat apps build previews on the server, which never sees the
  fragment, so all share links show the same generic preview.
- **Very large Events** create long links. Browsers handle them, but some chat apps may truncate
  very long URLs.
- **Browser support:** requires `CompressionStream` / `DecompressionStream` (Chrome 80+,
  Firefox 113+, Safari 16.4+). On unsupported browsers, Share shows "Sharing is not supported in
  this browser." and a received link shows the invalid-link banner.
- **Clipboard** requires HTTPS or localhost. GitHub Pages is HTTPS. Opening `index.html`
  directly from disk (`file://`) is not supported for sharing.
