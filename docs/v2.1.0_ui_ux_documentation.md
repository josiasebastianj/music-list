# setlist.app v2.1.0 — UI/UX Documentation

## 1. Design Direction

v2.1.0 introduces a visual direction combining:

- **Editorial Light Mode**
- **Modern Dark Mode**

The two themes share the same information architecture and interaction model.

The goal is to make setlist.app feel:

- focused
- clean
- music-oriented
- practical
- less generic / less dashboard-like
- comfortable for both light and dark usage

---

## 2. Core UX Principle

The main information architecture is:

> **Sidebar = Navigation**  
> **Main area = Workspace**

All Songs are listed in the sidebar.

Only the currently selected Song is displayed in the main workspace.

This avoids displaying the same Song information twice.

---

## 4. Header

The header contains:

1. `setlist.app`
2. Theme toggle
3. `Actions`
4. `Reset`

On mobile the tagline is removed to preserve horizontal space.

The header uses compact controls rather than large dashboard buttons.

---

## 5. Theme Toggle

Light/Dark Mode is a direct header control.

It is intentionally **outside** the Actions dropdown because theme switching is a frequent UI preference rather than a file/data operation.

The control displays the current theme:

```text
☼ Light Mode
☾ Dark Mode
```

---

## 6. Actions Dropdown

The Actions dropdown groups less-frequent data operations:

```text
Actions ▾
├── Export JSON
└── Import JSON
```

Reset remains outside the dropdown because it is a destructive action.

The dropdown closes when:

- an outside area is clicked
- Escape is pressed

---

## 7. Event Area

The Event area communicates the context of the current setlist.

It contains:

- Event label
- Event Name
- Event Date

Event information belongs to the Event, not to individual Songs.

---

## 8. Song Navigation

The sidebar lists all Songs.

Each navigation item displays:

- Song number
- Song Title
- Base Key
- Navigation indicator

Example:

```text
01  Build My Life          G   ›
02  Goodness of God        D   ›
03  What a Beautiful Name  A   ›
```

The active Song receives a distinct visual treatment.

---

## 9. Main Song Workspace

Only the active Song is displayed.

The workspace contains:

```text
Song Title
Base Key
Move Up
Move Down
Delete
Export PNG

SONG DETAILS
...
```

This makes the selected Song the focus of the application.

---

## 10. Song Controls

Song-level controls include:

- Edit Song Title
- Edit Base Key
- Move Song Up
- Move Song Down
- Delete Song
- Export PNG

There is no Collapse/Expand control in v2.1.0.

The previous Collapse/Expand behavior was removed because the workspace only displays one Song at a time.

---

## 11. Song Details UX

Each Song Detail has:

- Drag/reorder affordance
- Color indicator
- Name field
- Note field
- Move up
- Move down
- Delete

Example:

```text
⋮⋮  ●  INTRO
        Start after 4 bars       ↑ ↓ Delete

⋮⋮  ●  VERSE 1
        Acoustic guitar         ↑ ↓ Delete

⋮⋮  ●  CHORUS
        Full band               ↑ ↓ Delete
```

The note is attached directly to the relevant Song Detail.

---

## 12. No Song-Level Notes

v2.1.0 intentionally does not provide a separate Song Notes field.

The reason is information ownership:

```text
Song
└── Song Details
    └── Note
```

A note should be attached to the specific part of the Song it describes.

This prevents two competing note locations.

---

## 13. Color System

Song Detail colors provide quick visual grouping.

The colors are intentionally restrained and pastel-like in Light Mode while remaining visible in Dark Mode.

Colors communicate the section identity without becoming the dominant UI element.

---

## 14. Empty States

When an Event contains no Songs, the Song navigation displays:

```text
No songs yet.
Use + Add Song to start.
```

The main workspace displays a larger empty-state message:

```text
Your setlist starts here.

Add a song from the sidebar to create your first Song Workspace.
```

This communicates the next action without requiring a tutorial.

---

## 15. Add Song Flow

The user selects:

```text
+ Add Song
```

The new Song:

- has an empty title
- has an empty Base Key
- has zero Song Details
- becomes the active Song
- focuses the Song Title field

This minimizes setup friction.

---

## 16. Song Detail Flow

A Song starts with no details.

The user selects:

```text
+ Add Song Detail
```

and then builds the Song progressively.

This avoids forcing an arbitrary default structure onto the user.

---

## 17. Reordering UX

There are two independent reorder systems.

### Song reorder

Changes the order of Songs in the Event.

### Song Detail reorder

Changes the order of details inside the selected Song.

These two operations do not affect each other.

---

## 18. Destructive Actions

Delete Song and Delete Song Detail are explicit destructive actions.

Delete Song confirms that all Song Details belonging to the Song will also be removed.

Reset confirms that the complete Event will be cleared.

---

## 19. Export UX

### JSON

JSON is an Event-level operation.

It is available through:

```text
Actions → Export JSON
Actions → Import JSON
```

### PNG

PNG is a Song-level operation.

It is available directly from the active Song workspace.

The exported PNG follows the current Light/Dark theme.

---

## 20. PNG Visual Language

The exported Song image follows the application's visual language:

- Event context at top
- Song Title as primary heading
- Base Key as prominent metadata
- Song Details below
- Notes positioned beside their related Song Detail
- Author and version footer
- `setlist.app` branding

The export is designed as a usable Song sheet rather than a screenshot of the web UI.

---

## 21. Footer

The application footer contains:

```text
setlist.app

Author: josiasebastianj
Version: 2.1.0
```

The same branding/version information is included in exported PNGs.

---

## 22. Typography

The design combines:

- expressive serif typography for major Song/Event headings
- clean sans-serif typography for controls, metadata, notes, and labels

This creates the intended Editorial Light / Modern Dark character.

---

## 23. Light Mode

Light Mode emphasizes:

- warm off-white surfaces
- dark text
- subtle borders
- generous whitespace
- restrained shadows
- pastel Song Detail colors

The visual target is closer to an editorial/printed setlist than a generic SaaS dashboard.

---

## 24. Dark Mode

Dark Mode emphasizes:

- deep charcoal/navy surfaces
- light typography
- subtle surface separation
- restrained borders
- vivid but controlled section colors

The structure remains identical to Light Mode.

---

## 25. Responsive Design

Mobile design priorities:

1. Keep the header compact.
2. Keep Theme, Actions, and Reset accessible.
3. Move Event/Song navigation above the workspace.
4. Use a compact Song grid.
5. Allow Song controls to wrap.
6. Give Song Details enough vertical space for notes.
7. Stack footer metadata.

The mobile layout is not simply a scaled desktop layout.

---

## 26. UX Principles

The v2.1.0 redesign follows these principles:

- **Focus over density**
- **Navigation separated from editing**
- **One active Song at a time**
- **Contextual controls**
- **Minimal card styling**
- **Purposeful whitespace**
- **Restrained color**
- **Theme consistency**
- **No redundant Song-level notes**
- **No unnecessary Collapse/Expand interaction**
