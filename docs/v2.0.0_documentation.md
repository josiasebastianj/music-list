# setlist.app v2.0.0 — Documentation

## 1. Release Information

- **Application:** setlist.app
- **Version:** 2.0.0
- **Release type:** Major release
- **Author:** josiasebastianj
- **Baseline:** v1.5.2
- **Primary change:** Multi-song Event architecture

---

## 2. Overview

setlist.app is a lightweight web app for organizing songs and their song details/sections for an event.

Version 2.0.0 changes the application structure from a single-song model into a multi-song Event model:

```text
Event
└── Songs
    └── Song
        └── Song Details
```

One Event can now contain multiple independent Songs. Each Song has its own title, base key, and Song Details.

---

## 3. Data Model

The v2.0.0 Event state is conceptually:

```js
{
  eventName: "",
  eventDate: "",
  songs: [
    {
      id: "...",
      title: "",
      baseKey: "",
      sections: [
        {
          id: "...",
          name: "",
          color: "...",
          note: ""
        }
      ]
    }
  ]
}
```

### Event

Event-level properties:

- `eventName`
- `eventDate`
- `songs`

### Song

Each Song contains:

- `id`
- `title`
- `baseKey`
- `sections`

### Song Detail

Each Song Detail contains:

- `id`
- `name`
- `color`
- `note`

---

## 4. Initial State

When the application is opened for the first time:

- Event Name uses its default value.
- Event Date uses its default value.
- There are **no Songs**.
- There are therefore no Song Details.

The initial state is intentionally the same as the Reset state.

---

## 5. Reset

Reset restores the Event to its initial state:

- Event Name returns to its default value.
- Event Date returns to its default value.
- All Songs are removed.
- All Song Details belonging to those Songs are removed.

A confirmation is shown before the reset is performed.

---

## 6. Songs

The main content area contains the **SONGS** section.

### Add Song

Clicking `+ Add Song` creates a new Song with:

- Empty Song Title
- Empty Base Key
- No Song Details
- Expanded state

A new Song does not contain a default Song Detail.

### Song Editing

Each Song supports editing of:

- Song Title
- Base Key

The Song Card also provides controls for managing the Song.

### Song Reordering

Songs can be moved:

- Up
- Down

Song ordering is independent from the ordering of Song Details inside each Song.

### Song Collapse / Expand

Each Song can be collapsed or expanded.

When collapsed, the Song still displays its basic identity:

- Song number
- Song Title
- Base Key

When expanded, its Song Details are visible.

A newly added Song starts expanded.

The expanded/collapsed UI state is not part of the persisted Event data.

### Delete Song

Deleting a Song removes:

- The Song
- All Song Details belonging to that Song

A confirmation is shown before deletion.

---

## 7. Song Details

Song Details follow the behavior established in v1.5.2.

Each Song can contain zero or more Song Details.

### Add Song Detail

Clicking `+ Add Song Detail` creates a blank Song Detail:

```js
{
  id: "...",
  name: "",
  color: DEFAULT_SECTION_COLOR,
  note: ""
}
```

### Song Detail Editing

Each Song Detail supports:

- Editing the detail name
- Editing the note
- Changing its color
- Deleting the detail
- Moving the detail up
- Moving the detail down

### Empty Song Details

There is no default Song Detail.

A newly created Song starts with an empty `sections` array.

---

## 8. PNG Export

PNG export is now performed at the **Song level**.

One export produces one image for one specific Song.

The exported image contains:

1. Event Name
2. Event Date
3. Song Title
4. Base Key
5. All Song Details belonging to that Song
6. Author information
7. Application version

Other Songs in the Event are not included in that Song's PNG export.

### Export Layout

The Song Details export layout preserves the established v1.4.6/v1.5.2 composition:

- Song Title is positioned on the left.
- Base Key is displayed beside the Song Title.
- Song Title top alignment follows the top border of the Base Key badge.
- Song Details are displayed below.
- Notes are positioned on the right with a larger, more readable font.
- The PNG height accounts for multi-line Song Detail names and notes.
- Exported content is sized so the footer is included within the generated image.

### PNG Footer

The exported PNG contains:

```text
Author: josiasebastianj
Version: 2.0.0
```

The footer is placed at the bottom of the exported image.

---

## 9. Event-Level JSON Export / Import

JSON export/import operates at the **Event level**.

A single JSON file contains:

- Event Name
- Event Date
- All Songs
- All Song Details belonging to each Song

This allows a complete Event to be backed up or transferred as one file.

The application validates and normalizes imported data before using it.

---

## 10. Persistence

The application persists Event data in browser `localStorage`.

Persisted data includes:

- Event Name
- Event Date
- Song ordering
- Song Title
- Base Key
- Song Detail ordering
- Song Detail name
- Song Detail color
- Song Detail note

Temporary UI state such as Song collapse/expand state is not part of the persisted Event model.

---

## 11. Migration and Compatibility

Version 2.0.0 includes migration support for the previous single-song data model.

### v1.5.2

```text
Song
└── Song Details
```

### v2.0.0

```text
Event
└── Songs
    └── Song
        └── Song Details
```

Existing v1.5.2-style single-song data can be migrated into an Event containing one Song.

The migration is handled through state normalization so that the application can continue working with previously stored data rather than requiring the user to recreate it manually.

## 15. Release Baseline

The immediate previous stable baseline was v1.5.2.

v1.5.2 provided:

- Single-song structure
- Song Title
- Base Key
- Song Details
- Song Detail notes
- Song Detail color
- Song Detail reorder
- Song Detail deletion
- Event metadata
- localStorage persistence
- JSON export/import
- PNG export
- English UI terminology

v2.0.0 preserves these core behaviors while introducing the Event → Songs architecture.

---

## 16. Future Development Reference

When extending the application, preserve the following hierarchy:

```text
Event
├── Event Name
├── Event Date
└── Songs
    ├── Song 1
    │   ├── Song Title
    │   ├── Base Key
    │   └── Song Details
    ├── Song 2
    │   ├── Song Title
    │   ├── Base Key
    │   └── Song Details
    └── ...
```

Song-level behavior and Song Detail behavior should remain independent.

PNG export should remain Song-specific unless a future release explicitly introduces an Event-level export feature.
